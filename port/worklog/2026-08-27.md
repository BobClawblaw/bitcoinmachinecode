# 2026-08-27 — ARM port worklog

## node_log production-log format: match x86 exactly (timestamp FIRST)

USER: "log file is fucked ... With timestamp before anything else" + want real
durable data in the repo, nothing in /tmp.

Root cause: port/arm64/node_log.S `node_log_str` PREPENDED the level KIND tag
(`SERVE `/`BLOCK `/`INFO ` ...) to every line before the caller's buffer. The
callers (ibd.c / ibd_lsm.c) already build their buffer as
`"YYYY-MM-DD HH:MM:SS.mmm <msg>"` (mirroring asm/daemon/log_ts.h), so the
resulting line was kind-first:
    SERVE 2026-08-27 07:33:51.313 node start (ibd_lsm ...)
x86 production format (log_ts.h) is timestamp-first:
    2026-08-27 06:41:04.130 [txrelay:5] 44.251.42.22: +1 tx accepted ...
Fix: node_log_str now emits the caller buffer as-is (timestamp first, no KIND
prefix). node_log_event is left as the raw "<KIND> a b c" low-level form.
Verified with a 6-line unit check:
    2026-08-27 08:04:53.091 node start (ibd_lsm resumable LSM download worker)
    2026-08-27 08:04:53.091 h7360 txs=1 utxo=7024 spent=0 sigs=0 runs=13
Rebuilt ibd + ibd_lsm with node_log.o.

## ibd_par: multi-client (<=16) parallel downloader — LOG PARITY with x86 node
USER: "not seeing startup banner / 16 clients / a lot missing... I want log parity."
Root cause: ibd_lsm was a SINGLE-peer downloader logging only sparse BLOCK/STORE
lines. The x86 daemon (asm/daemon/main.c) prints a startup banner (L3774) and
runs its boot catch-up across up to `catchup_workers` (default 16) parallel
clients, logging [catchup] <host> / [dl] heartbeat.

New port/arm64/ibd_par.c: resumable LSM-UTXO-backed downloader that keeps the
ENTIRE verified consensus/apply/UTXO path of ibd_lsm byte-for-byte and replaces
only the single-socket fetch with a poll(2) mux over up to 16 CONCURRENT peer
sockets (in-flight windows = #clients, applied in strict height order ->
MISSING_PREVOUT=0 preserved). Adds:
  - x86 startup banner (===== bmc-bitcoind LOG START ... =====) as first output.
  - per-client "[catchup] client N connected: <host> fd=M (LSM-RESUME)".
  - "[dl] progress: X/Y blocks verified, N clients, live utxo=Z" heartbeat every
    1000 blocks.
  - bounded nonblocking TCP dial (6s) so dead-partner fallback is fast.
Bugs fixed during bring-up: (a) g_fd[] was initialized to -1 AFTER the connect
loop, wiping every connected fd -> req_window(-1) no-ops, poll spins, 0 progress;
(b) bounded dial left fds NONBLOCKING and the p2p handshake isn't EAGAIN-safe ->
handshake always failed, client loop spun; fixed by clearing O_NONBLOCK after
dial; (c) [dl] heartbeat printed next_apply-start (negative) instead of next_apply.
Verified: 4 clients, 512 blocks h154500..155011 MISSING_PREVOUT=0 (live 1209336,
MATCH); 16 clients 1200 blocks h155012..156211 MISSING_PREVOUT=0 (live 1222443,
MATCH), all 16 clients + banner + [dl] heartbeat in data/logs/bitcoind.production.log.
