## node_log production-log format: match x86 exactly (timestamp FIRST)

USER: "log file is fucked ... With timestamp before anything else" + want real
durable data in the repo, nothing in /tmp.

Root cause: port/arm64/node_log.S `node_log_str` PREPENDED the level KIND tag
(`SERVE `/`BLOCK `/`INFO ` ...) to every line before the caller's buffer. The
callers (ibd.c / ibd_lsm.c) already build their buffer as
`"YYYY-MM-DD HH:MM:SS.mmm <msg>"` (mirroring asm/daemon/log_ts.h), so the
resulting line was kind-first:
    SERVE 2026-08-27 07:33:51.313 node start (ibd_lsm ...)
x86 production format (log_ts.h) is timestamp-first:
    2026-08-27 06:41:04.130 [txrelay:5] 44.251.42.22: +1 tx accepted ...
Fix: node_log_str now emits the caller buffer as-is (timestamp first, no KIND
prefix). node_log_event is left as the raw "<KIND> a b c" low-level form.
Verified with a 6-line unit check:
    2026-08-27 08:04:53.091 node start (ibd_lsm resumable LSM download worker)
    2026-08-27 08:04:53.091 h7360 txs=1 utxo=7024 spent=0 sigs=0 runs=13
Rebuilt ibd + ibd_lsm with node_log.o.

## ibd_par 16-client crash h177612: stack-buffer overflow in version payload
The 10,000-block 16-client run crashed after ~9.9k blocks with
"*** buffer overflow detected ***: terminated". Diagnosis:
- NOT scriptSig size: t_sigsize.c scanned h177000..177700 -> no scriptSig > 520
  (max ~252); sigb[520] is NOT the trigger in this era.
- ROOT CAUSE: connect_peer builds the P2P version message into `unsigned char
  v[102]` but a minimum version msg is ~103 bytes (with the fixed U/A it writes
  byte index 102 = ONE PAST the array). A 16-client run does many
  connects/reconnects over ~10k blocks, so this stack-frame corruption
  accumulates and is eventually detected as heap/stack "buffer overflow".
- FIX: v[102]->v[256] in ibd_par.c, ibd_lsm.c, ibd.c, live_blocks.c,
  live_download.c; also enlarged the fixed sigb[520] scriptSig copy to
  sigb[10000] (defensive; consensus scriptSigs can exceed 520 in other eras) in
  ibd_par/ibd_lsm/ibd.
- Verified rebuild; fresh 16-client segment launched from h177660.

## FAST download now PROGRESSES (stall fixed) + IP byte-order + seed-node bootstrap
- ROOT STALL CAUSE (fixed): when a client's reconnect failed, rotate_client set
