# 2026-08-27 — ARM port worklog

## node_log production-log format: match x86 exactly (timestamp FIRST)

USER: "log file is fucked ... With timestamp before anything else" + want real
durable data in the repo, nothing in /tmp.

Root cause: port/arm64/node_log.S `node_log_str` PREPENDED the level KIND tag
(`SERVE `/`BLOCK `/`INFO ` ...) to every line before the caller's buffer. The
callers (ibd.c / ibd_lsm.c) already build their buffer as
`"YYYY-MM-DD HH:MM:SS.mmm <msg>"` (mirroring asm/daemon/log_ts.h), so the
resulting line was kind-first:
    SERVE 2026-08-27 07:33:51.313 node start (ibd_lsm ...)
x86 production format (log_ts.h) is timestamp-first:
    2026-08-27 06:41:04.130 [txrelay:5] 44.251.42.22: +1 tx accepted ...
Fix: node_log_str now emits the caller buffer as-is (timestamp first, no KIND
prefix). node_log_event is left as the raw "<KIND> a b c" low-level form.
Verified with a 6-line unit check:
    2026-08-27 08:04:53.091 node start (ibd_lsm resumable LSM download worker)
    2026-08-27 08:04:53.091 h7360 txs=1 utxo=7024 spent=0 sigs=0 runs=13
Rebuilt ibd + ibd_lsm with node_log.o.
