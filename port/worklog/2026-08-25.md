## secp256k1_scalar.S (scalar arithmetic mod the curve order n) -- DONE
Scalar elements = 4 little-endian u64 limbs. Exports same ABI as
asm/secp256k1_scalar.asm: sc_add(r,a,b), sc_sub, sc_mul, sc_sqr, sc_inv
(Fermat a^(n-2)). DELTA = 2^256-n fold (8 rounds) + 3 conditional n-subs.

Write carried over from prior session (uncommitted). This run:
1. Rebuilt from scratch -> found test_scalar SEGFAULTED (the stale binary had
   never actually been run to green).
2. Fixed AAPCS bug: sc_mul used callee-saved x22 as scratch (LAddr DELTA /
   N_LIMBS) WITHOUT saving it. main holds a live pointer in x22 across the
   sc_mul call, so after sc_mul returned x22 was garbage and later
   `st1 [x22]` faulted (SIGSEGV). Pushed/popped x22 in sc_mul prologue/epilogue.
3. After the crash fix, add/sub/mul/sqr PASSed but sc_inv wrong. Differential
   fuzz (oops -- first manual repro used big-endian hex strings, which fz_sc
   reads as LE limb-groups, so that repro was bogus and actually correct;
   re-fed the LE (fe4) encodings to get the REAL failing case) exposed sc_mul
   itself failing on full-range operands, off by exactly DELTA: exp - got = DELTA
   (i.e. the fold under-reduced by one DELTA).
4. Root-caused via round-by-round cur dumps (gdb .gdb script): Phase-1 16-product
   accumulation was CORRECT (product == a*b); the money bug was in the FOLD's
   carry-propagation loop:
       .Lcar: add x14,x14,#1 ; cmp x14,#10 ; b.hs done
              ldr x6,[x21,x14] ; adcs x6,x6,xzr ...
     The `cmp x14,#10` between the prior `adcs` and the next `adcs` CLOBBERS the
     C flag, so the carry out of tmp[k+1] was silently dropped at tmp[k+2] on
     every product add. Net effect: ~1 carry lost per fold column -> off by DELTA.
     Fixed by driving the loop with `cbnz` + plain `sub` (neither touches NZCV),
     so the adc chain carries flow uninterrupted to tmp[9]:
       add x14,x13,#1 ; mov x15,#10 ; sub x15,x15,x14 ;  (x15 = 8-k iters)
       .Lcar: ldr x6,[x21,x14,lsl#3]; adcs x6,x6,xzr; str ...
              add x14,x14,#1; sub x15,x15,#1; cbnz x15,.Lcar
     SCA_ADD (phase 1) was already unrolled (no cmp between adcs), which is why it
     was correct -- only the folded loop had the clobber.
