## Approach
- Same exported symbols/ABI so repo harnesses and the daemon link unchanged.
- The x86 original INLINES field add/sub via FE_* macros for speed; this port
  instead CALLS the already-verified fe_add/fe_sub/fe_mul/fe_sqr from
  secp256k1_fe.S. Correctness over speed; macro inlining is a PERF_SCOPE later.
- We could NOT use the repo's test_point_repr.c: it differentials against
  FROZEN x86-64 reference asm (tests/point_ref.asm, *_ref symbols) that won't
  link on ARM. So I built a fresh oracle: fuzz_point.py with an independent
  pure-Python Jacobian secp256k1 implementation (add-2007-bl, dbl-2009-l,
  mixed add, double-and-add scalar mul) driving the C driver fz_point.c.

## Verification
- repo test_point.c (point_double(G) == 2G affine): PASS native.
- fuzz_point.py: ~83,000 vectors across 7 seeds, 0 failures. Covers
  point_double/add/add_mixed/add_mixed_zr/scalar_mul, out-of-place AND
  in-place (r==p aliasing), and degenerate shapes explicitly injected
  (q==p/doubling branch, opposite->infinity, affine (0,0), Z==0), plus the
  z-ratio H out-parameter for add_mixed_zr.

## Bugs fixed (all caught by the oracle / gdb)
1. scalar_mul held loop state (R, base affine, table base, kbuf) in x19/x20/x22.
   But point_add / point_add_mixed / point_double CLOBBER x19..x22 with their
   own r/p/q/zr pointers. Result: table base destroyed -> all scalar results
   garbage (k=1 didn't even return G). root cause found with gdb dumping TAB
   intact but R scrambled. Fix: hold ALL scalar_mul loop state in x23..x28,
   which the leaf point_*/fe_* never write (they only touch x0-x18 and
   x19-x22). Registered this as a new skill pitfall.
2. top-of-file `.section .note.GNU-stack` pulled all following code into the
   note section (point_double "defined in discarded section" link error).
   Moved the directive to end of file.
3. window-loop control used plain `sub x28,x28,#1` (no S) so the flags for
   `b.mi`/`b.pl` were STALE, causing the remaining-windows loop to over-run
   even when only the top window existed -> 16x doublings scrambled R.
   Fixed to `subs x28,x28,#1`. Spot-checked every flag branch in the file is
   now preceded by cmp/subs.
