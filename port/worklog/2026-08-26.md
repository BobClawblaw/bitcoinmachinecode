## s7 FIX #2: large-tx preimage-scratch overflow (4MB-required work buffer) (2026-08-25)
Found when the deep 0..400000 run (367 min) aborted SIGABRT at h177659 with 3.3M
SIGFAIL/MISSING exploding from h134329. Dumped block 134329 tx16 (68KB, 2000-output
P2PKH spam spend) -> standalone sv_verify_script() returned 2 (EVAL_FALSE).
ROOT CAUSE: NOT script/crypto logic. legacy_sighash() materializes the RAW
input/output serialization into the caller's `work`/preimg scratch to build
hashPrevouts/hashOutputs; ibd.c passed only work[1<<16] (64KB). A 69KB tx
overflows -> legacy_sighash rc=0 -> checksig can't build the digest -> EVAL_FALSE
on EVERY large tx. 546k small-tx sigs passed (fit in 64KB); failures started
exactly at the first big spam tx (h134329, 2000 outputs).
VERIFICATION: t_sighash (4MB preimg) gave authoritative bitcoinlib-matching digest
4e1ddaa6... for tx16; sv_checksig with 8MB work returned sighash=4e1ddaa6,
pubkey_parse=1, ecdsa_verify=1, sv_verify_script->0 (OK). Fixed ibd.c: work =
malloc(8<<20), pass cap=8u<<20 to sv_verify_script.

## ---- 2026-08-26 session 2 (cron): ROOT CAUSE FOUND+FIXED: bitcoin_utxo.S blob-cap dangling-slot ----

### Symptom (carried from prior runs)
Deep-lived IBD (~h139429/139430) SIGFAIL err=2 against a spend that the
blockchain says is VALID: prevout txid 248ca2dc..ef7606:0. Our UTXO returned a
67-byte P2PK script `410496b538...` (hash160 2d090c6f..), the real prevout is
P2PKH `76a91478843f1b...88ac` (hash160 78843f1b.. == hash160 of the spend's
scriptSig pubkey, proved in this session). I.e. the UTXO returned a DIFFERENT
output's record for key (248ca2dc..,0) == RECORD ALIASING.

### Steps this session
1. Confirmed the aliasing for real: hash160(scriptSig pubkey 04571924..) ==
   78843f1b.. -> real prevout is the P2PKH; our stored P2PK is another key's
   record (= record aliasing, not a crypto/checksig bug).
2. Structured IBD-pattern differential (many outputs/txid, consecutive idx,
   P2PKH/P2PK-length scripts, coinbase->spend batches, up to 90% load) over
   t_utxo: 100% clean everywhere -> put/get/del LOGIC is sound, not a generic
   table bug.
3. Reload of the old 62MB utxo.idx snapshot returned the key MISSING (it was
   already spent) and the snapshot was later truncated by a concurrent 0..399
   test run -> no direct reproduction from snapshot.
4. Live full replay 0..175000 in background (blob cap bumped to 1<<28/256MB):
   crossed h139430 and well beyond (h144200+) with ZERO UTXO-CHECK violations
   and ZERO SIGFAIL/MISSING (2.3M+ sigs verified). The previously-failing
   region is clean when the blob does NOT fill.

### ROOT CAUSE
utxo_put .found_empty wrote the slot HEADER (index+txid) and memcpy'd txid
FIRST, then checked blob capacity; on `.full` (cap exhausted) it returned 2
WITHOUT writing blob_off/value/script, leaving a live-looking slot with a
STALE blob_off. A later utxo_get found that key (txid+index match) and read the
stale blob_off -> ANOTHER (usually adjacent) record's script -> wrong-script
SIGFAIL. The blob is append-only and fill never shrinks on delete, so total
puts (incl. deleted) at 128MB (1<<27) reached cap around the failing era; once
fill hit cap every new-key put corrupted that key's lookup. Random fuzz never
caught it because its 8MB blob never filled.

### FIX (bitcoin_utxo.S)
Move the capacity check (`cmp newfill,cap; b.hi .full`) to the TOP of
.found_empty, BEFORE any slot write; only after passing do we write the slot +
record + bump fill. Also fixed a latent register hazard: the slot-write path's
memcpy_asm clobbers x8/x9/x11, so hold `fill` in callee-saved x24 across it and
recompute slot base/record base after the bl.

  FIXED -> put2=2, get2=0 (absent), get1 intact.

  (every full put yields absent, every dup stays present); OLD FAILS=942

- Original fuzz_utxo.py + structural fuzz_utxo_ibd.py (incl. 80-90% load):

- ibd rebuilt with fixed object; short 0..220 sanity clean end-to-end.

### Diagnostics added (ibd.c)

  alias. Zero false positives on real 0..220 data.
