# 2026-09-08 — Core's REST interface, differentially proven

`rest=1` (default 0, Core's) serves the fourteen `/rest/` routes of Core's
`src/rest.cpp` on the JSON-RPC listener, unauthenticated as in Core, in
`.json`, `.hex` and `.bin`, with Core's status codes and error texts
(`text/plain` + CRLF): tx, block, block/notxdetails, blockpart, headers,
blockhashbyheight, chaininfo, mempool/info and contents, deploymentinfo,
blockfilter, blockfilterheaders, spenttxouts, getutxos (URI form and POST
body). Every route is answered from the node's own RPC handlers under the
per-dispatch lock (`asm/rest.c`).

Two deliberate details. `getutxos`' POST body is parsed as Core actually
parses it: the body is length-prefixed before being read, so any non-empty
body checks the mempool and the outpoint count is the body's first byte.
`mempool_sequence=true` is refused with a message: this node keeps no
mempool sequence number, and a made-up counter would be an approximate
answer.

## The differential

`validation/rest_regtest_diff.sh` starts a regtest Core with `-rest=1` and
this node with `rest=1` on one chain (Core mines, this node syncs), then
asks both every route in every format: 82 checks, status and body byte for
byte, json compared as ordered documents. The accepted divergences are
named in the script: `size_on_disk`, `warnings`, `coinbase_tx` (a Core
master field past the v31.1 target), `usage`, `unbroadcastcount`, and the
v31.1-versus-master `getmempoolinfo` skew; the verbose mempool listing is
noted rather than compared (`getrawmempool` verbose lacks the ancestry
fields, a known next slice).

The first run had thirteen failures. Four were RPC parity defects the
unit suite had passed, fixed in this batch: `getblock`/`getrawtransaction`
inputs emitted `prevout` after `sequence` (Core: before); `gettxout`
ignored `include_mempool` (a mempool-spent output is null, a
mempool-created one is answered with 0 confirmations); `getdeploymentinfo`
reported mainnet heights on every chain and no regtest `testdummy` (now a
BIP9 state machine after Core's versionbits.cpp); the mempool budget was
MiB where Core's `-maxmempool` is MB of 1,000,000 bytes.

Tests: `test_rest` (82 checks), `test_mempool_shared` +1, `test_node_config`
+2. Tag `core-rest-2026-09-08`, PR #115.
