# 2026-09-09 — The BIP68 sequence cap is sized from the block weight limit

At 00:31Z the bench node, 91% through a fresh sync, rejected mainnet block 880,338 as `bad-txns-nonBIP68-final`, invalidated it, and refused every chain that contains it: "tx 1114 has 7244 inputs, past the sequence window". `val_read_tx` recorded at most 2,048 input sequences per transaction and flagged the rest as truncated, and the BIP68 pass refused the block rather than treat the surplus as final. A valid block, rejected; a consensus failure. Production, synced past that height on an older build, carries the same code at the tip and would have forked on the next such block.

- The cap is 24,576, derived from the weight limit: a non-witness input is at least 41 bytes counted four times, so no transaction in a valid block has more than 4,000,000 / 164 = 24,390 inputs. The truncation refusal stays as a guard for a shape no valid block can hold.
- The bench was relaunched on the fix and the invalidation lifted with `reconsiderblock`; the run's clock is not a Core comparison (it already straddled ten binaries).

`test_val_read_tx`: a 7,244-input version-2 transaction parses with every sequence recorded and the last one, a height lock, read rather than lost past the cap. **Watched to fail** on the old cap (2 of 4).
