# SysV AMD64 stack-alignment map (incident #20)

Generated by `scripts/abi_stack_audit.py`. Regenerate with:

```

python3 ../scripts/abi_stack_audit.py --asmdir . --objdir . --format functions
```

> **This document is about ALIGNMENT ONLY.** There is a second, independent SysV
> obligation -- that `rbx`, `rbp`, `r12`, `r13`, `r14`, `r15` survive a call --
> and this tree was broken on it in twenty-one functions while every table below
> was green. See LOG.md incident #27, `scripts/abi_callee_saved_audit.py`
> (`make callee-saved-check`) and `asm/tests/bench_abi_audit`. A function passing
> `make abi-check` says nothing about whether it preserves registers, and vice
> versa. The fixes for #27 were deliberately parity-neutral -- reordering pushes,
> not resizing frames -- so every number in this document is unchanged by them.

## The rule

**At the `call` instruction RSP must be 0 mod 16.** The callee therefore sees
8 mod 16 on entry (the return address the `call` pushed), and its `push rbp`
restores 0. Compiler-generated C relies on this to place 16-byte-aligned SSE
spills; glibc's `vsnprintf` does `movaps %xmm0,-0xc0(%rbp)`, which on a frame
that is off by 8 raises #GP and is delivered as SIGSEGV **with `si_addr` NULL**.
That NULL fault address is the signature of an alignment trap, not of a
null-pointer dereference. See LOG.md incidents #18 and #20.

## How to read this table

Each assembly function is analysed twice, in isolation, under both possible
entry parities:

| isolated verdict | meaning |
|---|---|
| `ABI-CORRECT`    | every call is aligned when entered at 8 mod 16 (the ABI's parity) |
| `NEEDS-ENTRY-0`  | every call is aligned only when entered at 0 mod 16 — i.e. it violates the ABI when called correctly, and is only quiet while its caller is also broken |
| `MIXED`          | no entry parity makes every call aligned; the function is internally inconsistent (usually an unpaired `push`/`call`/`pop` bracket) |
| `SELF-ALIGNING`  | snaps with `and rsp,-16`, correct either way |
| `NO-CALLS`       | leaf; parity is irrelevant |

`entered at` is the set of parities the whole-program fixed point actually
delivers, starting from the exported entry points at 8. A function that is
`NEEDS-ENTRY-0` **and** is only ever entered at 0 is **compensated**: it is
correct *because* its caller is broken, and fixing that caller breaks it.
There is exactly one in this tree — `siphash24_uint256.sipround2` — and it is
why a naive global fix is not safe.

`leaves asm` counts misaligned calls whose target is C, libc, or an indirect
function pointer. Those are the ones that can fault today; `make abi-check`
enforces that this column is zero everywhere. The remaining asm→asm
misalignments are latent (every `movdqa` in this tree is register-to-register,
with no 16-byte-aligned stack operand anywhere) and are the outstanding
coordinated change.

`misaligned before` is at `cb20051` (main); `misaligned after` is at the tip of
this branch.

## Outstanding: the coordinated change

262 asm→asm call sites are still misaligned. They cannot be fixed one function
at a time, because changing a caller's frame size changes the entry parity
every callee below it receives. The order that works:

1. **Freeze the invariant first.** `make abi-check` already fails on any
   misaligned call that leaves assembly, so no new live instance can land while
   the rest is cleaned up.
2. **Fix the compensated site before its caller.** `siphash24_uint256.sipround2`
   has no prologue of its own and is only ever entered at 0. Give it a
   `sub rsp,8` / `add rsp,8` bracket *in the same commit* that adds `sub rsp,8`
   to `siphash24_uint256`, or the two `call .sipround`s inside it flip from
   correct to misaligned.
3. **Fix roots, then re-run, then repeat.** Work down from the exported
   functions that are `NEEDS-ENTRY-0` while entered at 8 (they violate the ABI
   today). Fixing one flips its whole callee subtree from entry 0 to entry 8,
   which *fixes* every `ABI-CORRECT` callee and *breaks* every `NEEDS-ENTRY-0`
   one — so the analyser must be re-run after each root, not at the end.
4. **`MIXED` functions need per-site edits, not a frame resize.** They are
   almost always an unpaired `push`/`call`/`pop` bracket. Pair the push (as
   `b18114b` did in `node_serve_loop`, and as this branch did in
   `interp_checkmultisig`).
5. **Check for `[rsp+N]` operands before resizing any frame.** Growing the
   reservation is only free when the locals are rbp-relative or sit at the low
   end of the frame. `interp_checkmultisig`, `stack_swap_two` and several
   `bitcoin_utxo_lsm.asm` functions address locals off RSP.
6. **Leave `bitcoin_utxo.asm` / `bitcoin_utxo_lsm.asm` / `bitcoin_utxo_store.asm`
   for last, and give them their own commit.** They hold the largest `MIXED`
   cluster, they are the most safety-critical code in the project, and a wrong
   frame edit there corrupts the UTXO set rather than crashing. Where a single
   call in one of those functions leaves assembly, prefer the `sub rsp,8`
   bracket used for `lsm_mm_invalidate_all` — zero blast radius.

The proof obligation for each step is mechanical: dump the classified call-site
set before and after, key it on `(file, function, target)` so line shifts do not
register, and confirm that no group's misaligned count increased.
