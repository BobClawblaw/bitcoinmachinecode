## M2: the heap (branch perf/2026-10-08-m2-memory)

The operator asked why bmc used twice Core's memory and how to stop using
70 GB. The breakdown of run 41's 75.6 GB peak, and what was built, are in
`worklog/2026-10-05-performance-holes-plan.md` (the 2026-10-08 section):

- The merge child and the flush writer are forked without the buffers they
  never read, so the parent's writes copy nothing for them. This was the
  32 GB heap peak.
- `dbcache` is the total: the live memtable and the frozen copy get half
  each.
- The frozen copy releases its pages when its writer is adopted.

## B14: the dead-weight rule and the full window (branch fix/2026-10-08-dead-weight-window)

Run 42's 29 bans came from the dead-weight rule during the merge stall,
not from the stall rule (B13 banned nobody). A worker waiting at the full
window was measured over the whole tick and dropped as dead weight. The
rule now judges only the time a worker was free to fetch. Built during
run 43, tested with `test_dialhelper` only (built at nice 19); the full
gate waits for run 43 to end so the box stays quiet.

## The settle count, and why run 44 waited (branch fix/2026-10-08-b12-settle-count)

Run 44 passed (MuHash = Core at 970,536, ready 4:02:04, 0 bans); #412
merged (15b2ce7f) and run 45 launched 22:26:50Z on it. Its ranges took
21.5 s for all 19, but the settle line said "4 peer(s) holding none
stopped" when three had fetched. The download worker runs with SIGCHLD =
SIG_IGN, so a range child that exits is auto-reaped and `waitpid(pid,
WNOHANG)` fails ECHILD; it never returns the pid, which is all the parent
compared against. No exit was ever seen: before #412 the loop could only
end at its 180 s cap, which is the real cause of run 44's 182 s (the idle
peer was a bystander). The test ran with SIGCHLD at its default and could
not see it. The straggler takeback also did a blocking `waitpid` after
SIGKILL, which under SIG_IGN waits for every child (the 09-24 hang in
`dl_reap_bounded`'s comment).

Fix: the three reaps use `dl_reap_bounded` / `dl_kill_reap`; the 0.5 s
grace waits for every peer, and the line names who was still connected:
`every range settled in Ns; N peer(s) still connected stopped (N never
served a page)`. `test_dlc_header_probe` now runs every phase under
SIG_IGN, as the worker does, and the first ranges case checks no peer is
stopped. With the old reaps put back it fails 2 checks and prints run
45's "4 peer(s) ... stopped"; with the fix 59/59, three runs. Full gate
after run 45.
