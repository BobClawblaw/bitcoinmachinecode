# 2026-08-27

A production mempool freeze, then the real fix for it (Core-style byte-budget
eviction), the parked wallet-encryption WIP finished and shipped, and full

## incident: production mempool froze at exactly 4096 (00:00–01:00)

- [x] **Root cause:** `tx_accept`'s shared policy state (`mempool_cfg.c`) was
      sized to a fixed 4096 entries — the pool stopped accepting at exactly
      4096 with ~1.2 MB of a 300 MB blob used. `unsigned long pn = slots`
      (was `4096`) sizes it to the pool's real slot capacity (~216 MB for 1M
      slots). Hotfix `70a754a`, deployed immediately as
      `bitcoind.deploy-20260827o-hotfix`.

## Core-style mempool management (01:00–01:30)

- [x] The freeze exposed a design gap: the pool **rejected** new txs when full
      instead of **evicting** cheap ones. Rebuilt it Core's way
      (`c4e908c` → `be85835`, deploy **`p`**):
- [x] **TrimToSize eviction** (`bitcoin_mempool_policy.c`): on a full pool,
      evict lowest-feerate LEAF txs (leaf = `desc_cnt==1`, Core's
      self-inclusive convention) until the incoming tx fits, never evicting
      one paying ≥ incoming. Divergence stated: individual-leaf, not
      descendant-package, eviction.
- [x] **blob compaction** (`daemon/mempool_compact.c`): the pool's
      bump-allocator never reclaimed freed bytes, so eviction freed a slot but
      no space — compaction slides live regions down (O(n log n)) before each
      store retry.
- [x] **dynamic `mempoolminfee`** = last evicted feerate + incrementalrelayfee;
      txs below it rejected up front; `getmempoolinfo` reports max(relay,
      floor). (Floor moved off the accepted-bytes accumulator offset — a
      collision found in test.)
- [x] **config-wired** (defaults == Core): `minrelaytxfee`,
      `incrementalrelayfee`, `limitancestorcount`/`size`,
      `limitdescendantcount`/`size`, `mempoolfullrbf`. Boot logs `[config] mpol`.
- [x] tests/test_mempool_evict + full suite green (186). Live on deploy `p`:
      `getmempoolinfo` reports the dynamic floor; `[config] mpol` confirmed.

      tests/test_aes.
- [x] **crypter** (`daemon/wallet_crypter.c`): Core's BytesToKeySHA512AES KDF +
      a sealed container (salt, iters, AES-CBC-wrapped seed, SHA-256 checksum);

      tests/test_wallet_crypter.
- [x] **state machine** (`daemon/wallet_enc_state.c`): boots an encrypted store
      LOCKED, unlock re-derives the seed from the sealed mnemonic and installs

      state module without `main.c`.
- [x] Fixed the WIP build breaks (a `wseed` typo; an unbalanced brace from the

## regtest chain selection — proven against Core (02:25–02:51)

- [x] The node now runs mainnet OR regtest, selected by `chain=regtest`
      (or `regtest=1`) in bitcoin.conf. Everything chain-specific moved behind
      `daemon/chainparams.{h,c}` with a **static MAINNET default**, so any
      process that never selects a chain is byte-identical to before
      (`110e2ee` → `7acf207`).
- [x] Chain-selected: net magic (runtime dword in `bitcoin_net.asm`, `fabfb5da`
      on regtest), P2P/RPC ports (18444/18443), the **genesis block** (derived
      from the mainnet bytes — nTime/nBits/nNonce patched, Core's own
      construction — then **hash-ASSERTED against Core's `hashGenesisBlock`**
      before selection can succeed), the script-flag schedule (runtime selector
      in `bitcoin_script_flags.asm`; regtest heights GENERATED from
      CRegTestParams by the same `gen_script_flags.py`), subsidy halving (150),
      GBT next-work (fPowNoRetargeting), address params (0x6f/0xc4/bcrt), the
      RPC chain name, dns_seeds=off.
- [x] **Datadir isolation** (operator requirement): Core's layout — mainnet at
      the datadir root, regtest under `<datadir>/regtest/`, bitcoin.conf shared
      at the root. Logs live in `<chain-datadir>/logs/`, filename chain-tagged
      (`bitcoind.log` / `bitcoind.regtest.log`). Fresh non-main datadirs
      self-seed genesis at archive index 0.
- [x] **Four latent bugs the first regtest boot flushed out** (all would bite
      a fresh mainnet datadir too): fresh `headers.dat` off-by-one (every block
      stored one height low — a getheaders response never includes the locator
      point); the download worker re-`chdir`'ing to the BASE datadir (split one
      chain's state across two dirs); `connect=` peers dropped by the public-IP
      book filter (loopback Core → permanently-offline worker); hardcoded 8333
      in six dial sites + two `out_port` call sites.
- [x] **Proven against a scratch Core regtest** (build/bin/bitcoind, ports
      18444/18460):
      - Core mined 160 blocks; bmc synced them; **all 161 heights
        byte-identical** (getblockhash 0..160), tips equal.
      - `gettxoutsetinfo muhash` **identical** (`4599bb4c…def34a1`), height 160,
        txouts 160, total 7725 BTC — which also proves the halving-at-150
        arithmetic (149·50 + 11·25).
      - A block built from **bmc's OWN `getblocktemplate`** (height 161,
        coinbasevalue 2 500 000 000 — halved; bits 207fffff — no retarget) was
        CPU-mined and **ACCEPTED BY CORE via submitblock**; both tips advanced
        to the same hash.
      - Live-follow: Core mined more, bmc tracked the tip in real time (166=166).
      - Tx relay: a Core wallet tx reached bmc's mempool over the regtest wire.
- [x] tests/test_chainparams — 29 checks (genesis derivation vs Core's asserted
      hashes on both chains, asm globals flipping, regtest flag schedule,
