## LIVE keep-up: serve loop now stores peer-pushed blocks; node_sync fixed for REAL mainnet (not just fake peers) [DONE]
- **Requirement**: "whenever bitcoind runs it should automatically run the
  download loop so it's up-to-date as soon as new blocks are generated."
  Previously `bitcoind serve` was inbound-only and could never advance its own
  store: it relayed `inv`->`getdata` but dropped the `block` response ("inbound
  keep-up is the downloader's job"), and it had NO outbound connections, so it
  had no source for new blocks. The outbound `node_sync`/`node_drain` had only
  ever been tested against the in-process fake 8-block peer.
- **asm/bitcoin_serve.asm**: added the missing `.do_block` receive half -- an
  inbound `block` message is now `cons_verify`-validated, its hash re-derived
  and duplicate-guarded via `idx_get`, then `store_append`d and `idx_put` so it
  is immediately serveable by hash O(1). Every non-consensus/garbage/duplicate
  block is rejected (the earlier fake-style blocks with a non-matching merkle
  root were correctly refused). The store tip advances and the existing tip-
  watch `.next` announces the new tip (BIP130 inv/headers) exactly once.
  Made the serve loop long-running (unbounded; terminates only on connection
  close) so the node stays up instead of exiting after the old 10000-iteration
  budget. Fixed a hard crash: `cons_verify` does NOT preserve r12-r15 (it only
  pushes rbp/rbx), so a `.do_block` call to it clobbered the serve loop's live
  fd/st registers -> stable fd/lfd statics + explicit restore (same discipline
  already used for st/ht_idx).
- **asm/bitcoind.asm node_sync -- TWO REAL-MAINNET BUGS FOUND BY LIVE TESTING**
  (only exposed by a live seed; the fake 8-block peer never triggered them):
  1. **Interleaved-relay crash**: node_sync assumed "send getheaders -> the
     very next read is `headers`" and "send getdata -> the next read is
     `block`"; a real seed interleaves addr/sendheaders/feefilter/inv/ping
     between our request and its answer, so the strict first-read check failed.
     Fixed with `.hdr_drain`/`.blk_drain` loops that echo ping->pong and ignore
     any other non-target message, failing only on a real read error (<=0).
  2. **Stack overflow / SIGSEGV**: node_sync prehashes up to `hcount` block
     headers into a 64 x 32B array at rbp-0xae8; a live seed returns up to
     2000 headers per getheaders page, so hcount>64 wrote hash[i] far past the
     array, stomping the locator ([rbp-0x78]) + save area and SIGSEGVing.
     Fixed by computing the page's varint offset from the REAL count and
     capping the PROCESSING count to 64 (node_sync re-requests from the
     advanced locator to fetch the rest). Fake peers only ever sent <=8.
- **daemon/main.c serve mode**: added `outbound_catchup()` -- best-effort,
  non-fatal: resolves real mainnet seeds, `node_handshake`s, and runs the
  verified `node_sync` headers-first catch-up anchored to the store's STORED
  TIP (so it pulls only the missing tail; zero-locator full download when the
  store is empty), then serves. Any seed/network failure falls through to
  serving -- the daemon can never hang offline.
- **tests/test_keepup.c (NEW)**: closes the loop with a deterministic
  loopback test -- peer pushes a block the server lacks; asserts it is absent
  before, then validated+stored+SERVED byte-exact after, and that a duplicate
  push is a no-op that keeps the server alive. Wired into `make test`.
- **LIVE mainnet verification (this is REAL data)**: on an empty store,
