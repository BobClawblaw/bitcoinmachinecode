## Persistent UTXO store to disk [DONE]
`asm/bitcoin_utxo_store.asm` extends the in-memory UTXO set (`bitcoin_utxo.asm`)
with a crash-safe, reloadable on-disk layer mirroring the proven store/index
pattern of `bitcoin_store.asm`:

- **utxo.dat** — append-only OPERATION LOG (WAL). Every mutation is a framed
  record appended at the current log length: PUSH `[u32 magic "UTXO"][u8 op=1]`
  + txid(32) + index(u32) + value(u64) + slen(u16) + script; DEL `[op=2]` +
  txid + index. Replaying PUSH/DEL in order reconstructs the exact UTXO set —
  this is the durable source of truth.
- **utxo.idx** — POSITIONAL INDEX / CHECKPOINT: `[magic "UTXI"][log_off u64]`
  + n(u64) + n live records `[txid32][index4][value8][slen2][script]`, written
  by `utxo_store_sync` (which fsyncs BOTH files). On reload the snapshot is
  restored O(n) and only the log TAIL past log_off is replayed — so a crash
  between checkpoints is recovered by tail replay (restart-resume).
- Thin durable wrapper over the untouched in-memory table: `utxo_store_init/put/
  del/get/count/sync/reload/close`. Every put/del writes the WAL first, then
  applies in memory; get/count tail-call the in-memory primitives.

`tests/test_utxo_store.c` (throwaway temp dir) verifies: put/get round-trip +
value/script, spend + double-spend miss, dedup-leaves-table, RESTART-resume both
(a) full WAL replay with no checkpoint and (b) checkpoint + crash-tail replay
(final live set correct after puts/spends across a sync), on-disk framing byte
checks (rec0 header 54B, magic UTXO, op PUSH, txid/index/value/slen; idx magic
UTXI, header ckpt_n). **ALL TESTS PASSED (0 failures), exit 0.**

Also fixed a latent golden-rule bug in `bitcoin_utxo.asm`: `utxo_put`/`utxo_get`
stored their locals at `[rbp-0x28..-0x38]`, which for a 5-push frame overlaps

redeem + a 2-of-2 multisig redeem), the empty-script negative, a

`ecdsa` oracle `asm/validation/p2sh_oracle.py` (separate EC math from the repo's

`ecdsa_verify` accepts the sig over it. Wired into `make test`; stale

test_p2pkh, test_txval, test_wallet, test_utxo all PASS).

DEBUGGING (4 distinct root causes, all fixed):
- ABI: `multisig_verify` originally read `inputIndex` from r10 and `work` from
  [rbp+16], but SysV passes the 7th arg on the stack — so `work` came out as
  inputIndex=0 and sighash wrote to a NULL preimage (SEGV). Re-ordered to read
  inputIndex/work/workCap/prevOut/prevOutLen from [rbp+16..48].
- Stack shadow: the frame allocated 0x120 but used locals down to [rbp-0x1c0]
  (r_out/s_out/Qx/Qy/z/sighash), so nested calls overwrote them → wrong z /
  ecdsa failure. Grown to `sub rsp, 0x200` (matches verify_p2pkh).
- Scan semantics: the original scan computed "sigLen = byte at (pubDataStart-1)",
  which reads the pubKey's OWN length byte (33) as the sig length. Rewritten to
  track the PREVIOUS push and use it as the sig (the only correct layout for
  `[dummy][sig][pub]`).
- Test vector was malformed (the tx's embedded scriptSig was 1 byte short —
  missing the SIGHASH_ALL trailing byte — so its CompactSize length disagreed
  with the content and the sequence read misaligned). Regenerated with
  `asm/validation/gen_vector.py` into a 187-byte, internally-consistent tx.

## mempool policy + RBF / fee handling [DONE]

Policy layer on top of the structural mempool (`bitcoin_mempool.asm`) and the
UTXO set (`bitcoin_utxo.asm`). `bitcoin_mempool_policy.c` is PURE C glue over
the verified asm primitives (same model as `wallet_core.c`), and enforces the
full acceptance pipeline atomically (any policy failure leaves the structural
mempool and policy state untouched):

- **fee computation + min-relay-fee floor** — resolves each input value
  (mempool-produced output first, then confirmed UTXO via `utxo_get`); rejects
  negative fee and `fee < vsize * relay_fee_rate`.
- **double-spend rejection** — a second tx spending an already-claimed prevout
  is rejected.
- **BIP125 RBF** — replaceable signalling (`any input nSequence != 0xffffffff`),
  new absolute fee >= sum(replaced fees) + incremental (`relay*1000`), and on
  accept the replaced txs are evicted (structural `mpool_del` + policy state
  unregister).
- **ancestor / descendant limits** — DFS-exact ancestor set per tx, rejected
  beyond `max_anc`/`max_anc_bytes`; every ancestor's descendant count/bytes
  budget checked and bumped on commit.
- **fee estimator** — EMA (k=4) of accepted feerates (sat/kB), exported via
  `mpool_policy_estimate_feerate`.

Verified by `tests/test_mempool_policy.c` against an INDEPENDENT pure-Python
oracle (`tests/gen_mempool_policy_vectors.py` -> `mempool_policy_vec.h`): 4
scenarios / 21 steps, every verdict and the exact EMA feerate must match. All
pass; the full offline suite is 35/35 green.

Also extended the asm structural mempool with `mpool_del` (RBF eviction),
covered in `test_mempool.c`, and fixed a stray `bitcoin_wallet_cli.o` phantom
entry in the Makefile OBJS (no such source; it broke `make asm`).

Design note: policy logic lives in C (not NASM) by explicit choice — the card
does not mandate assembly, and this mirrors the already-accepted wallet-CLI
precedent of "verified asm primitives driven from C". The heavy crypto/storage
stays asm; policy is bookkeeping/control-flow.

verify_p2pkh (bitcoin_script.asm): validate a P2PKH input spend end to end in
