## The coinstats ring: bursts, not a slow worker (branch perf/2026-10-10-csi-ring)

The 60 s perf at ~740k (pdiag) put 42% of the applier's context switches in
`ring_push` sleeping on a full coinstats ring; run 46 booked 414 s under
`csi`. Run 46's fold worker folded 7.21 billion elements over 11,850 s, about
608k/s, at ~445 ns a MuHash insert: 30-40% of a core on average. Run 47 at
700k, each process's /proc CPU over 60 s (no RPC): connect process 88%, fold
worker 36%, index worker 7%. The worker keeps up; the 64k-entry ring (12 MB)
holds only a few heavy blocks (~20k records each), so a run of them puts the
connect thread to sleep.

- `RPC_CSI_RING` 65,536 -> 524,288 entries (96 MB of anonymous shared memory,
  not persisted; the overrun bound and the lap detection scale with it).
- `slot_fill`: release fences in place of the two `__sync_synchronize`
  (mfence) per record, paid 7.2 billion times a sync on the connect thread;
  the worker's reads take acquire fences, including one after the first
  `ready` check that was missing (a non-volatile copy may be hoisted above a
  volatile load). Compiler barriers on x86, dmb on ARM.

`test_coinstats_fold_ring` 3a: 200,000 records into a paused worker with the
wait bound at 0 find room every time; with the 64k ring, 134,464 overrun.
