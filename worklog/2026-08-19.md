## Session 2: hashtype dispatch extended to P2PKH and P2SH -- Stage B closed

Closed the "remaining" item above. Work happened on worktree

- [x] Extended `validation/gen_hashtype_vectors.py`: refactored the P2PK-only
      generator into a `group_checksig()` battery reusable across script
      shapes, then applied it to P2PKH and P2SH(P2PK redeem) -- same
      genuine/tamper-unbound/tamper-bound/ANYONECANPAY/SINGLE-quirk pattern
      already proven for P2PK. For P2SH, `legacy_sighash`'s scriptCode
      argument is the REDEEM script, not the outer `HASH160..EQUAL`
      scriptPubKey -- matching Core's `pbegincodehash` semantics inside the
      P2SH sub-script execution.
- [x] Added a P2SH(2-of-2 multisig redeem) group with two co-signers using
      DIFFERENT hashtypes on the SAME input (NONE + SINGLE) -- genuinely
      separate coverage from the CHECKSIG cases above, since CHECKMULTISIG
      builds its own `interp_slice` at a different site in
      `bitcoin_interp.asm` (`.cms_loop`, not `interp_checksig`). Tamper
      pair proves BOTH co-signers' hashtypes are independently honored:
      tampering an output neither signer's hashtype binds still accepts;
      tampering the one output the SINGLE co-signer binds rejects (breaking
      the 2-of-2 threshold even though the NONE co-signer doesn't care).
      Plus a wrong-key negative control (2-of-2 count enforcement survives
      non-ALL hashtypes, not just field-mismatch rejection).
- [x] `tests/test_hashtype_e2e.c`: extended to read a new per-vector
      `HT_FLAGS` array (P2SH cases need `SV_P2SH` set; P2PK/P2PKH need 0).

## Session 3: Stage C -- activation-height flag schedule

Work happened on worktree `wt/scriptverify-stagec` (`.worktrees/t_stagec`);
production untouched.

- [x] Read Core's REAL `GetBlockScriptFlags` (`src/validation.cpp`) instead
      of assuming the textbook "P2SH activates at height 173805" shape the
      plan was written with. Found something the plan didn't anticipate:
      current Core has P2SH/WITNESS/TAPROOT active from height 0
      UNCONDITIONALLY, with exactly two historical mainnet blocks
      identified by HASH (not height) where the flags get overridden down
      to something weaker. DERSIG/CLTV/CSV/NULLDUMMY (NULLDUMMY activates
      with segwit, BIP147) ARE height-gated the textbook way, each at its
      own real threshold. So Stage C's planned pure `script_flags_for_height(h)`
      became `script_flags_for_block(height, hash32)`.

      `verify_flags_for_height` in the demoted `bitcoin_verify.c` gated
      P2SH at a hardcoded 173805 and applied DERSIG/CLTV/CSV/NULLDUMMY at

      silent deletion.
