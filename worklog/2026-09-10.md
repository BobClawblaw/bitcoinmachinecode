## 2026-09-10 — the IBD-blocking bugs (found by the first regtest run)

- THREE raw-svc sites kept the Linux nr-in-x8 convention after the
  mechanical rewrite: idxscan_append_locked's TWO flock sites
  (x8=32 -> x16=131) and node_log_open's openat (w8=56 -> x16=463).
  Darwin executes whatever garbage sits in x16: nosys slots raise
  process-directed SIGSYS (the worker died on signal 12 at random PCs --
  si_code 0, interrupted PC in plain C code, because the bad syscall was
  on another thread), and real numbers fire the WRONG syscall (the first
  crash, signal 11, was the fd-close roulette). Fixed all three; the
  worker has been stable since.
- bitcoind.S node_make_version double-dereferenced _node_services
  (x86: `node_services dq 9` is a plain u64 that main.c ORs into). The
  extra `ldr` read address 0x809 (NODE_NETWORK|WITNESS|P2P_V2 as a
  POINTER) -> SIGSEGV in dl_catchup's probe handshake. macOS
  DiagnosticReports .ips gave the clean backtrace
  (node_make_version+36 <- node_handshake+44 <- dl_catchup) without any
  debugger: lldb attach AND batch launch are permission-gated on this
  macOS 26.6 build (also true under `script` PTYs). Single-load fix.
- cons_twin.c txid_of_span (the osx twin computes txids itself because
  x86 asm tx_txid hashes the wrong length for segwit txids): the first
  cut hardcoded the marker+flag offset (tx+6), eating two bytes of every
  LEGACY txid, and passed the txid-slot cap where the scratch byte cap
  belongs (67-byte tx > 64 slots -> refuse -> cons_verify 0).
  test_cons 14/14 after both fixes; txid == sha256d(tx) for legacy and
  the stripped form for segwit. Found by the gate before it could bite
  mainnet (blocks 1..479k are all-legacy coinbases).
- asm/daemon/main.c: SIGSYS/SEGV/ILL/BUS/FPE/ABRT handler in the
  download worker dumping siginfo + native backtrace to stderr --
  the diagnostic that made the syscall-roulette crashes legible.
- asm/daemon/ibd_pipeline.c: on IBD_FAIL_CONSENSUS dump the offending
  block bytes to /tmp/ibd_bad_<pid>_<ts>.bin with its block hash, for
  offline analysis (standalone cons_verify passed every block of the
  failing chunk, so the arriving bytes were the question).
- Process lesson (again): build_daemon.sh only recompiles stale objects;
  a manually-built twin object or a half-edited source can leave the
  daemon binary inconsistent with the tree. The first mainnet chunk run
  failed cons_verify (code -5) on every chunk with a binary that did not
  match the tree; a clean full rebuild (which briefly failed its own
  link on my undeclared `time()` -- one more reason the link step must
  be allowed to fail loudly) made chunks pass with the same inputs.
  Rule going forward: touch a port source -> rebuild ALL, then run.

## 2026-09-11 (late) — the script-VM wave gets its gates; the real TLS bug

- Ran the upstream harnesses natively against the ported objects (the
  roadmap's DONE bar for the wave committed in bc38f9e8, which had landed
  with "gates = the daemon itself"). FIRST REAL GATES for interp +
  scriptcodec: test_nop1_regression SEGFAULTED immediately.
- Root cause (two layers, found with macOS .ips crash reports, an
  in-test siginfo+backtrace handler, and a 30-line isolated repro --
  lldb still permission-gated):
  1. The Mach-O TLV getters turned x86 TLS_ADDR (inline gottpoff+fs:0
     arithmetic, clobbers ONLY its destination) into a CALL that returns
     in x0 -- clobbering the caller's x0 argument (hnd_begin stored the
     getter's return where main_elems belonged) and, fatally, LR.
  2. THE RULE: on AArch64 `ret` jumps to x30; a leaf .S function whose
     body now contains a bl (TLS_ADDR) must save/restore x30 or its
     closing ret jumps to the last getter's return site. `sample` on a
     hung minimal repro showed the loop literally: asm_plain+4 ->
     asm_plain+4. x86 ret pops the stack; arm64 ret = br x30. The
     arm-port never hit this because ELF TLS access was inline too.
- Fix (0bac9e2b): TLS_ADDR now saves x30 + x0-x17, calls the getter, and
  delivers to \d by writing the result into \d's OWN save slot (offset
  i*8; the x30 pad sits below the pairs) so the pops restore everything
  except \d. First cut of the delivery used offsets 16+i*8 -- wrong by
  one pair slot; the isolated test's MISMATCH (0x120a8 = the caller's
  stale x2, a compiler constant, not stack junk) pinned it.
- Gates green natively on the ported objects after the fix:
  test_nop1_regression 9/9, test_checkmultisig_findanddelete,
  test_checkmultisig_zero_keys, test_checkmultisigverify_pop,
  test_sig_pushonly_75, test_cltv_csv 17/17, test_ir10_p2pkh_bounds 5/5,
  test_interp_legacy_spend 6/6, test_sigops, test_script_flags 13/13,
  test_mempool_wtxid 26/26, test_cmpct_recv 43/43 (needed net_twin for
  p2p_write; got a Darwin guard for the Linux cpu_set_t core pinning),
  test_private_broadcast, bench_idxscan, test_cons 14/14, hnd_begin/
  hnd_end round trip. consensus_shim builds. The wallet round trip via
  the live regtest node: getbalance 300.00000000 (six 50-BTC mining
  payouts tracked), getnewaddress derives, wallet store loads at boot.
- The mainnet node was RESTARTED onto the fixed binary (the running one
  predated the fix; its boot catch-up only stores blocks so it was safe
  so far, but the UTXO-connect handoff runs script verification on every
