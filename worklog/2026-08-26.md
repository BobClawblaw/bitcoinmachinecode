## the mempool gets fed — and the incident family that came with it (17:18–19:53)

- [x] **tx relay receive side** (`daemon/tx_relay.c`): peers announce txs on
      all eight full-relay legs; `node_sync_multi` was discarding every inv
      unexamined, so the production mempool had **never held a single P2P
      transaction**. Now drained between sync passes, requested as
      **MSG_WITNESS_TX** (bare MSG_TX returns the stripped form — incident
      #10's shape). tests/test_tx_relay, 15 checks (`a3bae03`).
- [x] **incident #47** — the worker's RPC-accepted txs were invisible to the
      parent's mempool RPCs: `tx_submit.c` still used a private 1024-slot pool
      while the parent read the shared `mempool_configure` pool. `txsub_pool()`
      now prefers the shared area (`a3bae03`).
- [x] **incident #48** — relayed txs mass-rejected: the `tx_accept` snapshot
      resolver could not coexist with a live UTXO writer; resolve against the
      live writer, fix relay drain ordering, add the NODE_WITNESS dial gate
      (`733b8cb`).
- [x] **incident #49** — `utxo_lsm_get`'s `slen` was a 4-byte store into
      8-byte callers → nondeterministic "prevout script too large"; the 64-bit
      slen contract + txval first-contact standardness caps (`b8903bb`).
- [x] **incident #50** — the caps raise left 16-sized taproot arrays → worker
      crash loop; fixed, legit-script caps, log summary restored (`f4cf591`).
- [x] **mempool admission now runs the CONSENSUS verifier** — one engine, not
      two (`e803730`). The architectural close of the #48/#49/#50 family:
      admission and block validation share `tx_verify_mempool`.
- [x] relay grows up: orphan pool + parent fetch, re-announce, getdata service
      (`3233557`). Announced-tx children whose parents are missing are parked,
