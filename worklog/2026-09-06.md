## Session 4 (13:00 →): the download lever, and the bug it exposed

- [x] **Archive guard landed**: the connect refuses a body that is not the
  block the index records at that height (`utxo_live.c`). A racing read can
  no longer file another block's coins under a height and turn the NEXT
  height into a false `bad-txns-BIP30`. Stops the pass like a hole; the next
  pass retries; `utxo_live_archive_mismatches()` counts them.
  `test_dlc_interleave` gained a reverse-order peer mode
  (`BMC_TEST_PEER_REVERSE=1`) — every fixture peer in the suite answered
  getdata in request order, so no test ever delivered an out-of-order chunk
  to the real connect loop.
- [x] **ROOT CAUSE of the pipelining failure found (16:00Z): a stale
  READER, not a bad archive.** Ran the decisive experiment -- pipelined build
  + the archive guard -- and the guard fired 14 times at height 2,845 while
  the false `bad-txns-BIP30` never appeared. Hand-parsed `index.dat` and
  `blk00000.dat` at 2,843-2,847: every record matches its body and the
  oracle, so nothing on disk was ever wrong. `bitcoin_store_fast.asm` caches
  a read fd and an mmap window per blk file; `store_reload` refreshes the
  index but drops neither, so the connect re-read the same stale bytes every
  pass and never advanced. The serial build wrote slowly enough to go 494k
  blocks without tripping it. Half the fix is landed (the guard, PR #49);
  the other half -- drop the caches and re-read -- is written, unproven, and
  parked on `batch/2026-09-06-ibd-pipeline-v2`.
- [ ] **Pipelined download: 12x measured, NOT landed.** One getdata per
  40-block chunk instead of one per block: 75,425 blocks in 6 min against
  the serial build's 74,638 in 74 min, same peer pool, same afternoon.
  Landed as PR #47 and **reverted in PR #48** — both pipelined runs died on
  a false `bad-txns-BIP30` (heights 48,585 then 74,765) on blocks the oracle
  confirms are ordinary. Ruled out: a shifted archive, arrival-order storage
  (fixed and it still failed), a store ordering hole (STO-11 holds on both
  append paths), and the new reverse-order fixture (passes with the fault
  present and absent — 600 blocks over 3 peers is not enough concurrency).
  Full write-up and the next step in `UTXO_INLINE_BUILD_PERF_SCOPE.md`.
- [x] **Benchmark run 4 running** since 13:17Z on `c1a4473`, 0 rejects.
